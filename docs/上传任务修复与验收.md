# 上传任务修复与验收

## 已实现

- 使用 `dataSync` 前台服务和上传进度通知，上传脱离页面 ViewModel；页面刷新、切目录、退出 Activity 不取消任务。
- 顶部“上传任务”入口支持查看任务、失败原因、逐任务取消、继续或重试，以及清理已结束的历史。文件选择支持多选；多个任务排队执行，各自拥有独立 ID 和进度。
- 提交时固定账号 ID、Bucket、目录和 endpoint，切换激活账号不改变任务目标。原账号删除后报错，不回退到其他账号。
- 任务记录、文件快照和断点位于 `noBackupFilesDir`，不保存 AccessKey/Secret，不参与系统备份。任务文件按唯一 ID 隔离。
- 首次上传将源文档完整复制为不可变快照，复制支持取消，半成品不作为有效快照。重试复用快照，原文档改变或授权撤销后也不会拼接不同版本的分片。
- **8 MiB 及以上**使用 OSS SDK `asyncResumableUpload`，保留检查点和已上传分片，点击“继续 / 重试”续传。小文件及零字节文件使用普通 PUT，重试从头发送。
- 分片大小至少 2 MiB，并按文件大小调整，限制分片数量。远端合并成功后才算任务完成；成功后释放本地快照和断点。

## 取消与历史清理

“取消上传”先将状态变为“正在取消”，取消对应协程并传递给 SDK。界面等到 SDK 请求收尾后显示“已取消”，随后可以继续或清理。取消单个排队任务不会停止其他任务。旧进度回调不能撤销取消状态，也不能重新插入已清理的记录。

取消保留快照和断点，便于随后继续；它不是回滚远端写入。如果取消时远端已经完成合并，对象可能已经存在。重试仍可能覆盖同名对象。

“清理历史”先显示确认弹窗，只清理已完成、失败、中断和已取消任务；上传、排队和正在取消的任务不会被移除。清理包括本地文件快照、SDK 断点和任务记录，清理期间禁止这些任务重新入队。文件清理失败时保留记录并提示重试。清理失败或取消任务后，原断点不再可用。

历史清理不会删除 OSS 已完成对象，也不会向 OSS 发送远端分片删除请求。未完成的远端分片需要由 Bucket 生命周期规则或管理端清理；本次不自动修改 Bucket 配置。

## 使用边界

- Android 13 及以上需要允许通知，拒绝后仍可在任务列表看进度。系统手动关闭通知渠道也会影响显示。
- 强制停止、进程被杀、重启或服务超时后不承诺自动恢复发送。再次打开应用时未完成记录显示中断，由用户点击继续；本地完整快照和断点保留。
- SDK 只复用服务端仍有效的分片；失效断点或已过期分片可能需要重新上传。网络断开后按 SDK 超时和重试策略转为失败，没有无限自动重试。
- 快照保留期间占用设备存储；清理历史可以释放失败、中断和取消任务的占用。完全卸载应用会失去记录及本地断点。
- 前台服务仍受系统和厂商资源策略限制，实际后台、熄屏和续传行为需要设备验收。

## 设备验收

1. 选择不同大小文件（0 字节、小于 8 MiB、恰好 8 MiB、大文件），并包含不同来源的同名文件。确认每文件状态和进度独立。
2. 上传中刷新、切换目录/账号、旋转屏幕，确认任务保留且目标仍为提交时的账号和路径。
3. 大文件上传期间退后台、熄屏，再打开，确认通知、任务终态及远端对象内容一致。
4. 大文件上传若干分片后断网，恢复网络并继续。结合 OSS 请求或 SDK 调试证据确认复用原 uploadId、查询已传分片并跳过对应分片；仅看到进度跳跃不能证明续传成功。
5. 分别取消排队、复制中和网络上传中的任务。等待“已取消”后继续，检查其他文件不受影响；反复快速点击取消/继续，确认不重复上传、不串进度。
6. 上传中强制停止并重新打开，确认显示中断；继续后核对分片复用。修改原始文档，确认已有快照继续上传原版本。
7. 同时保留上传中、排队、失败、中断和已取消任务，清理历史并确认：仅终态记录被移除，本地文件释放，远端已完成对象仍存在。
8. 清理时尝试重试或连续点击清理，检查无并发删除正在读取文件；模拟空间不足或读取失败，确认不遗留有效半成品。
9. 拒绝通知权限、撤销源文档授权、删除原账号并重试，确认提示明确；同时回归下载、删除和目录刷新。
