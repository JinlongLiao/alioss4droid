# 文件类型图标修正

## 修正结果

原来 APK 使用普通应用方块，JSON 与 HTML 共用源码符号，EXE、DMG、PKG 共用终端符号。回归测试已先复现六类文件只有三种图形的问题，再替换为独立语义图形。

| 类型示例 | 固定图形 |
| --- | --- |
| APK、AAB、APKS、XAPK、AAR、DEX | Android 机器人 |
| JSON、JSONC、JSONL、GeoJSON | 花括号与键值点 |
| HTML、HTM、XHTML、MHTML | 网页窗口与标签 |
| EXE、COM、SCR | Windows 四窗格 |
| DMG、ISO、IMG、VHDX、QCOW2 | 磁盘镜像 |
| PKG、MSI、MSIX、DEB、RPM | 封装箱 |
| APP、AppImage、IPA | 应用方块 |
| SH、BAT、CMD、PS1、Dockerfile | 终端 |
| YAML、TOML、INI、ENV、PLIST | 配置滑杆 |
| DB、SQLite、SQL | 数据库圆柱 |
| DLL、SO、DYLIB、WASM | 芯片 |
| PDF、Word、Markdown | 各自的 PDF、W、M 与箭头标识 |
| CSS、SCSS、SASS、LESS | 样式井号 |
| JAR、WAR、EAR、Java | 杯形 |

图片、音频、视频、表格、演示、压缩包、普通代码及字体继续使用各自类别符号。未知格式使用问号，不伪装为文字文档。

[30 组浅色/深色背景预览](设计资源/文件类型图标预览.svg) 从当前 Kotlin 矢量路径导出，使用示例文件名，不包含账号、Bucket 或真实对象信息。

## 跨主题一致性

- 同类型文件使用固定的形状和类别色，主题不再参与文件图标的选择或重建。
- 文件列表和预览加载页均调用同一映射，使用原色绘制，共享缓存。
- 页面背景、卡片、导航与目录图标继续使用现有主题配置。
- 深色与浅色背景可能影响半透明底面的观感，但文件的矢量路径与类别色完全相同。

## 名称解析边界

只读取路径最后一段的文件名，忽略扩展名大小写。优先处理完整配置名称、`.env.*`、Dockerfile 和 Makefile；普通文件按最后后缀分类，因此 `app.apk.zip` 为压缩包、`index.html.txt` 为文本。版本化共享库如 `libdemo.so.1.2` 仍识别为库文件。

`.ts` 在图标层优先按 TypeScript 展示，`.mts`、`.m2ts` 为视频。图标识别不更改预览、下载、执行能力，也不读取文件内容来判断真实 MIME。
