# 文件操作性能审查与修复

本轮针对文件排序、缓存、预览、上传后刷新及递归文件操作进行本地审查。以请求次数、线程位置、缓存完整性和资源关闭顺序验证改动，不以少量样本的毫秒耗时声称真机性能达标。未调用真实 OSS/S3 对象接口。

## 已确认问题与修复

| 问题与源码证据 | 修复及兼容边界 |
| --- | --- |
| 完整目录加载器已排序，ViewModel 又在 Main 对结果排序；缓存 JSON/磁盘读写也在 Main | 完整扫描和排序在 Default，缓存读写、失效及代次锁等待在 IO；直接发布加载器已排序结果。缓存恢复和设置切换的本地重排也移到 Default |
| 时间排序、名称倒序仅排序当前页不能得到全目录顺序 | 完整扫描当前层元数据，每页 1000、最多 10000 条；达到上限且仍有分页 token 立即明确失败，不再取下一页。名称正序保留分页；文件夹优先与排序定义不变 |
| S3 每页创建并关闭 SDK client；递归操作外层 client 之外再次创建分页 client | 同一目录扫描/递归操作共用一次操作范围内的 client，结束后关闭；不引入全局连接池，不改变凭据生命周期 |
| 多个完整大目录长期保留在无上限内存 map，TTL 仅重访时检查 | 访问顺序 LRU，仅内存限制 20000 个元数据条目和 32 个快照；写入时释放过期内存项。淘汰保留磁盘及 TTL，后续可完整从磁盘恢复，不截断结果、不淘汰失效代次 |
| 上传选择URI时在Main查询ContentProvider名称，慢云文档会阻塞界面 | VM只捕获URI/目标后立即启动FGS，任务名称由服务每任务IO准备阶段解析并持久化后再生成远端key；占位名不能直接上传，旧任务默认保持原名称 |
| 每个上传成功立即触发完整目录扫描；历史成功可能被重复当作新事件 | 使用仓库初始化时固定的成功 ID 基线；成功记录筛选在 Default。仅匹配当前账号/目录的新成功事件触发刷新，固定 250ms 窗口合并，连续完成不延长等待；立即使旧扫描代次失效 |
| 文本、DOCX、XLSX、PPTX、CSV 等下载完成后的解码/ZIP/XML 解析在 Main | 解析改在 Default；下载仍在 IO。保持原解析结果与已有内容大小上限；关闭、切账号、重新打开均取消旧预览并检查代次，旧结果不得覆盖新文档 |
| PDF 缓存仅按 key/name 命名，跨账号/Bucket 或同名覆盖会复用错误版本 | 使用 profileId、Bucket、key、etag、size、mtime 的 SHA-256 摘要命名；未知版本不复用。独立半成品下载后发布完整缓存，取消/失败删除半成品，不包含凭据 |
| PDF 在 Compose Main 一次渲染并持有全部页 Bitmap | 一个文档使用一个后台 native 会话，仅为 LazyColumn 可见/预取项渲染。render/close 互斥，关闭不阻塞 UI；取消后回收未交付 Bitmap，已交付 UI 的 Bitmap 只释放引用，不提前 recycle |
| 极大单页仍可能分配超大 Bitmap，极瘦长页可能超出 Compose 布局约束 | 单页最多 8000000 像素且单边最多 4096，内部等比降采样，内容完整不裁剪。显示尺寸单独按原页比例计算，普通页保持原宽度；极端比例整页缩到 16384px 安全布局边界并提示可下载原文件。极端大页的细节分辨率会降低 |
| produceState 更换 key 可能保留旧文档结果 | 按文档路径隔离 Compose 子树；页面状态按会话/页码/宽度隔离，同一文档旋转后继续复用 native 会话 |
| OSS 移动循环 copy 时重新读取当前激活账号，而 delete 使用外层旧 client | VM 在提交时捕获 profileId，mkdir/delete/move 和下载/预览按明确账号解析；一次 OSS move 的 copy/delete 始终沿用同一 client。禁止目录移入自身子目录，避免递归扫描新目标不断扩大 |
| 写操作仅刷新完成时的当前页面，可能留下源/目标或非当前目录旧缓存 | 按提交快照失效源/目标父目录，部分失败同样失效；递归变更在 IO 清理元数据缓存以覆盖全部后代。请求失效代次拒绝旧响应写回，仅仍匹配的可见目录自动重读 |

## 保留的操作语义

- 递归删除仍是逐对象删除；移动仍是逐对象复制成功后删除源。没有为了减少请求引入批量删除或无界并发，避免改变部分失败、取消和不可回滚行为。递归请求加入协程取消检查。
- 大文件下载仍采用流式复制，不把整个文件放入内存。仅小文件文本预览使用原有有界内存下载。
- 单目录 10000 条限制只保护需要完整元数据的全局排序；超限提示用户切回名称正序继续分页，不把部分数据伪装成全局排序成功。
- 缓存序列化与磁盘操作仍通过原实例锁串行保证代次一致性；ViewModel 不在 Main 等待这些操作。没有根据本地单测推断设备帧率或网络吞吐量。
- 上传仓库的历史批量清理、初始化及状态日志 IO 由独立上传任务完成，验收以对应报告和独立测试为准。
