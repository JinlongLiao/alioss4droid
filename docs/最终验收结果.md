# 最终验收结果

> 本文记录 SDK 升级前的阶段验收；1.0.5 正式版 SDK、安装结果和最新 APK 指纹以[发布与清理记录](1.0.5发布与清理记录.md)为准。

## 已交付

- AWS S3 配置接入现有文件模块，旧 OSS 配置兼容；Region 提供本地化地区选择、搜索和手动代码输入。
- 根据用户指定 Bean 的默认配置，在手机保存 S3 账号配置；真实 Android 的 `ListBuckets` 成功返回 4 个 Bucket，区域 `ap-northeast-1`。初次重启后配置保持，最终 APK 更新后也已确认 S3 配置项存在。未强制改变用户随后选择的其他 OSS 账号。
- 时间排序和名称倒序按完整当前目录元数据排序，上传完成按提交目标失效缓存；设置变更回到顶部，旧响应不能把缓存写回旧状态。
- 目录扫描、缓存读写、排序和文档解析移出主线程，扫描复用单次操作 SDK 客户端，连续上传刷新合并，内存缓存有 LRU 保护。
- 上传命令串行 IO 处理，前台服务先启动；进度按单任务原子记录持久化，终态可靠落盘后发布，批量历史清理仅提交一次。文件名查询可取消并移至 IO，真实名称保存后才构造上传 key。
- PDF 改为可见页按需后台渲染，补齐尺寸预算、跨文档隔离和关闭竞态保护；账号、Bucket 和版本隔离预览缓存。

## 验证边界

- 所有上传、下载、复制、删除、分片及文件列表协议测试都使用本机模拟服务和假凭据。真实 S3 仅调用账号级 `ListBuckets`，没有列举、读取、上传、复制、删除或 HeadObject 任何真实文件。
- Region 数据、连接配置及编译回归通过；最终搜索、自定义输入和取消的完整手机交互未验证。没有将设备控件定位失败等同于产品失败，也没有声称完整设备流程通过。
- 排序、刷新与上传事件链路通过本地回归和代码检查，没有执行真实 S3 文件操作来验证界面置顶。
- 后台上传长稳、弱网、系统杀进程及其他 Android 真机版本未实测。
- 完整时间/倒序扫描限制为当前目录 10000 条元数据，达到上限且还有下一页时立即提示；名称正序仍支持原按需分页。没有静默截断文件列表或宣称局部排序是全局有序。

## 配置和工作区

凭据仅保存在应用既有加密仓库。测试用明文凭据、反编译输出和中间配置文件已清理；临时配置探针已卸载。没有把凭据写进代码、资源或文档，也没有执行 Git 提交、推送或其他 Git 写操作。

Robolectric 测试缓存按用户 `settings.xml` 的实际 `localRepository` 展开用户目录变量；本轮误生成的项目相对缓存已移出，后续测试未再生成该目录。没有修改全局 Maven 配置。
